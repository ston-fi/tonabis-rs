# Moon offline binding generation

`bindings.json` is a normalized wire-schema/ownership manifest for the bindings, not an on-chain ABI claim. It retains the SHA-256 of each source
Rust module and the original type names, fields, selectors and widths. The source
SDK is `@moon-cx/sdk` 2.0.1 (`bc94fb40497738b9beed66d9b7bfda38b6cb9b8f`); catalog
revision is `7dc57067d85c95dc25c09ccaaf108eaba62f6303`. Notices and SDK metadata live
in `crates/moon`. `catalog-getters.json` records the 39 original catalog methods
and numeric selectors. Captured current selectors are regression-tested separately.

`bindings.sha256` pins the normalized schema. Review schema changes and their
independent wire evidence before updating the pin. `generate_bindings.py` needs
Python 3.9+ and no network, source checkout, SDK installation or executable cells.
It emits only the ordinary records and dispatch in its explicit allowlist. The remaining protocol
exceptions are handwritten. Most dispatch derives TLB; mempad uses explicit
opcode dispatch to preserve known-body errors from a nested internal transfer.

The generator can write **only** `generated_files` in the manifest. Wrapper APIs,
method results, shared messages/metadata/address helpers and all exception children
are excluded. Never put handwritten behavior in generated modules. The schema
path mapping records canonical ownership; it is not a compatibility re-export API.
The `scalar_results` section records removed one-field DTOs that map to native scalar getter returns.

```sh
python3 tools/reference/moon/generate_bindings.py
cargo fmt --all
python3 -m unittest discover -s tools/tests -v
cargo test -p tonabis_moon --locked
```

Before/after generation, hash handwritten files to check preservation. Repeat the
first two commands and require identical generated bytes. A changed hash pin does
not validate a wire change: the 315 independent wire vectors in
`crates/moon/src/tests/fixtures/wire-vectors.json` remain a separate oracle and
must not be rewritten to match the encoder. Default fixtures contain synthetic
records/program markers only. Math vectors, live acquisition, capture manifests,
executable replay and economic qualification tools are not included.

## Flat record ownership

A contract's msgs/storage file contains its types and their implementations.
Modules that combine schema records with authored codecs or construction methods
are maintained as complete flat files and excluded from generated outputs.
The generator must preserve them and never recreate former child modules.
For a mechanical authored move, unit tests and formatting suffice; generation
checks apply only when generator inputs or ownership change.
